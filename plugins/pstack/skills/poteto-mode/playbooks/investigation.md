### Investigation

**You own the answer. Plan, route, write.**

Investigation requests are read-only. They produce a cited explanation or a recommendation, not a code change.

1. Route through the **how** skill. For motivation questions, also route through the **why** skill. In an Effect codebase, run the effect skill's SKILL §1 version gate before explaining any Effect API, because v3, the 4.0.0 prereleases, and 4.0.0 read alike and behave differently.
2. Throughput checkpoint stays one line: `throughput checkpoint: n/a, read-only investigation`.
3. Produce the `how`-shaped output (Overview / Key Concepts / How It Works / Where Things Live / Gotchas), or a recommendation if the request is a decision between alternatives. Derive the recommendation with **reason-from-first-principles**, using the how and why findings as premises, and write it per distill-writing's `references/decision-writing.md` (see `../references/thinking.md`).
4. Select what the reply says with **distill-writing**, then apply the **unslop** skill.

No PR, no babysit, no `architect` unless the investigation precedes a code change. If it does, hand back to the user and re-route to Bug fix or Feature.

**Reply:** the investigation output. For "are we sure?" answers, include your real judgment with reasons. Push back if the premise is wrong (see Autonomy).
